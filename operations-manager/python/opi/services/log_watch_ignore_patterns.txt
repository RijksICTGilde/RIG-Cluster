# log_watch ignore-list - known-benign / known-recurring OPI log noise.
#
# One Python regex per line (re.search against the log MESSAGE). Lines starting
# with '#' and blank lines are ignored. Keep this TIGHT: anything not matched
# here escalates (an ntfy notification, plus Claude triage in the standalone CLI),
# so only add genuinely-understood noise.
# When a new benign pattern shows up in an alert, add it here.

# --- postgres: idempotent create on re-processing ---
Database .+ already exists on
Schema .+ already exists in database

# --- minio mc: bucket already created (backup flow re-creates blindly) ---
Unable to make bucket .+ already own it

# --- kopia: status check against not-yet-initialized repos (new/PR deploys) ---
Failed to connect to Kopia repository:.*repository not initialized

# --- argo: false "permission denied" while an app is mid-creation (auto-retries) ---
Permission denied accessing application
Error checking application creation status: Permission denied

# --- git: concurrent-write contention, auto-rebases and retries (recovers) ---
Push rejected .*attempting rebase and retry \(attempt \d+/\d+\)
# Raw git stderr from a non-fast-forward push that the connector then rebases and
# retries. Anchored to '^error:' so it matches ONLY git's own line, not the
# connector's terminal "Failed to push changes ... after N attempts" ERROR, which
# is unanchored and still escalates when all retries are exhausted.
^error: failed to push some refs

# --- kubectl: existence probes during create/delete (NotFound is expected) ---
# Also covers the metrics/OOM/tuning path iterating a project's declared
# components when the Deployment (and its VPA) never materialized - i.e. the
# project was never deployed, or a component has no image. A genuinely broken
# deployment surfaces as CrashLoopBackOff/ImagePullBackOff/degraded ERRORs, not
# a read-time "get ... NotFound", so those still escalate.
kubectl get (configmap|secret|application|deployment|verticalpodautoscaler).*Error from server \(NotFound\)

# --- API auth: rejected reads (missing/invalid key, missing param) ---
Authentication failed for route .+ - no .*API-Key provided
Authentication failed for route .+ - invalid API key
Missing .+ parameter for route
Master API key not configured - route .+ is disabled

# --- keycloak: existence check during processing ---
Client '.+' not found in realm

# --- keycloak: client scope already default on realm re-bootstrap (idempotent 409) ---
Failed to assign client scope as realm default

# --- project declared but not deployed yet - no Deployment to inspect ---
No deployments found in project

# --- kubectl: log fetch/stream transients while a pod is starting/rolling ---
kubectl logs.*Error from server \(BadRequest\)
Failed to get deployment logs.*Error from server \(BadRequest\)
error: unexpected EOF

# --- uvicorn: malformed / probe inbound HTTP on the listener ---
Invalid HTTP request received
