# Kopia Backup Image

Minimal Docker image for RIG's PVC backup system using Kopia. This image is designed to work with the BackupManager in the Operations Manager (OPI) for backing up and restoring Kubernetes Persistent Volume Claims (PVCs).

## Overview

This image provides:
- Kopia backup tool for incremental, deduplicated backups
- Minimal Alpine-based image for security and size
- Non-root user support (though pods run as root for PVC access)
- Timezone support for accurate timestamps

## Usage

This image is not meant to be run directly. It's used by the BackupManager when creating backup/restore pods for PVC operations.

### How it works in the RIG system:

1. **BackupManager** creates a backup pod with this image
2. Pod mounts the clone PVC (created from VolumeSnapshot)
3. Pod connects to S3 repository using environment variables
4. Kopia performs incremental backup with deduplication
5. Pod is deleted after backup completes

## Building

Build the image for multiple architectures:

```bash
# Build for current architecture
docker build -t kopia-rig:latest .

# Build for specific architecture
docker build --build-arg TARGETARCH=amd64 -t kopia-rig:latest .
docker build --build-arg TARGETARCH=arm64 -t kopia-rig:latest .

# Build with BuildKit for multi-arch
docker buildx build --platform linux/amd64,linux/arm64 -t kopia-rig:latest .
```

## Configuration

The image expects these environment variables when used in pods:

- `S3_ENDPOINT`: S3-compatible endpoint URL
- `S3_BUCKET`: S3 bucket name
- `S3_ACCESS_KEY`: S3 access key
- `S3_SECRET_KEY`: S3 secret key
- `KOPIA_PASSWORD`: Repository password (derived from project SOPS key)
- `BACKUP_PREFIX`: Repository prefix in S3 (e.g., `local/project-name`)

## Integration with BackupManager

The BackupManager (`operations-manager/python/opi/manager/backup_manager.py`) uses this image to:
1. Create backup pods with dynamic commands
2. Handle repository connection and snapshot creation
3. Apply retention policies
4. Handle error cases and cleanup

## Security

- Base image is Alpine 3.19 for minimal attack surface
- Kopia provides encryption at rest
- Each project has unique encryption key derived from SOPS age key
- Backup pods run with minimal required permissions

## Implementation Notes

This image is designed to work with the existing backup pod manifests that use `/bin/sh -c` to execute backup commands inline. The image provides:

1. Kopia binary in PATH (accessible as `kopia`)
2. `/bin/sh` as entrypoint for running shell scripts
3. `/data` as working directory where PVCs are mounted

The actual backup commands are dynamically generated by the BackupManager and passed as shell scripts to the container.
